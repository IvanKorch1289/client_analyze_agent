## 1. Краткий обзор проекта

### 1.1 Миссия и цели

**Миссия**: Автоматизация процесса комплексной проверки контрагентов с использованием искусственного интеллекта для минимизации рисков при заключении сделок.

**Ключевые цели**:
1. Агрегация данных из 7+ государственных и коммерческих источников
2. Автоматическая оценка рисков с использованием LLM
3. Генерация структурированных отчётов с рекомендациями
4. Соблюдение требований 152-ФЗ о персональных данных

### 1.2 Бизнес-ценность

| Показатель | Описание |
|------------|----------|
| **Целевая аудитория** | B2B-компании, осуществляющие проверку контрагентов |
| **Проблема** | Ручная проверка занимает 2-4 часа на одного контрагента |
| **Решение** | Автоматизированный анализ за 45-60 секунд |
| **ROI** | Сокращение затрат на Due Diligence в 10-20 раз |

## 3. Диагностика и проблемные точки

### 3.1 Критические проблемы (P0) 🔴

#### 3.1.1 Потенциальная утечка PII при ошибке маскирования

**Файл**: `app/agents/llm_manager.py:604-607`

```python
except Exception as e:
    logger.error(f"PII masking failed: {e}")
    return prompt, None  # ⚠️ Отправляет оригинал в LLM!
```

**Риск**: При сбое Presidio персональные данные отправятся в облачный LLM → нарушение 152-ФЗ.

**Решение**:
```python
except Exception as e:
    logger.critical(f"PII masking FAILED - BLOCKING LLM call: {e}")
    raise PIIMaskingError("Cannot proceed without PII masking") from e
```

**Оценка влияния**: Критический — потенциальное нарушение законодательства
**Сложность исправления**: Низкая (2 часа)

---

#### 3.1.2 Небезопасные CSP директивы

**Файл**: `app/config/security.py:93`

```python
csp_directives = "... 'unsafe-inline' 'unsafe-eval' ..."
```

**Риск**: Разрешает выполнение inline JavaScript → уязвимость к XSS атакам.

**Решение**: Убрать unsafe-* директивы, использовать nonce или hash.

**Оценка влияния**: Высокий — уязвимость безопасности
**Сложность исправления**: Низкая (1 час)

---

#### 3.1.3 Отсутствует настройка pii_masking_enabled

**Файл**: `app/agents/llm_manager.py:582`

```python
pii_masking_enabled = getattr(settings.secure, "pii_masking_enabled", True)
```

**Риск**: Настройка не определена в SecureSettings, зависит от default значения.

**Решение**: Добавить явное определение в `app/config/security.py`:
```python
pii_masking_enabled: bool = Field(
    default=True,
    description="Включить маскирование PII. НЕ ОТКЛЮЧАТЬ в production!"
)
```

**Оценка влияния**: Средний
**Сложность исправления**: Низкая (30 минут)

### 3.4 Архитектурные наблюдения

#### Сильные стороны архитектуры

1. **Чёткое разделение ответственности** — 4 независимых агента с единой точкой оркестрации
2. **State management** — TypedDict для типизированного состояния workflow
3. **Graceful degradation** — fallback chain для LLM и in-memory cache
4. **Observability** — OpenTelemetry + Prometheus + структурированные логи

#### Слабые стороны архитектуры

1. **Монолитный deployment** — все агенты в одном процессе (сложно масштабировать отдельно)
2. **Зависимость от LangGraph** — vendor lock-in на специфичную библиотеку
3. **Синхронная пагинация** — InfoSphere/Casebook могут занимать до 6 минут
4. **Отсутствует distributed tracing** между агентами
